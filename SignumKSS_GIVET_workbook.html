개발 검토의 기준

최초 개발계획서의 필수 기능을 중심으로 확인합니다.

MVP 필수 기능 우선
INPUT 01
기준·원천 데이터문서·품목·산식·규정·템플릿 확보
IMPLEMENT 02
핵심 엔진 구현RAG · BoQ · 룰셋 · 문서 출력
VERIFY 03
측정·실증실제 사례 시험, 결과 기록 및 KPI 비교
시안 생성 기능은 별도로 진행될 수 있지만, 최초 계획서상 권장(Should)으로 분류되었습니다.
RAG·내역 자동산출·규정 자동점검은 최초 계획서상 필수(Must) 기능입니다.
지금 미확인된 항목은 미개발이라고 단정하지 않고 실물 자료와 실행 결과로 확인합니다.

GIVET

지금 확인해야 할 핵심 질문

회의의 초점을 '의심'이 아닌 '작업에 필요한 입력과 증빙'에 맞춥니다.

01 / 자료
산식·단가·규정·제안서 원본은 누가 보유하며, GIVET에는 언제 어떤 형태로 전달할 수 있나요?
02 / 구현
RAG·BoQ·규정 엔진의 현재 상태는 무엇이며, 실제 입력·출력 예시를 공유할 수 있나요?
03 / 검증
공인시험과 파일럿을 위해 필요한 시험환경·기준값·로그를 어떤 방식으로 제공하나요?
사용 안내 자료 수령 여부는 현재 GIVET 관점의 미수령 상태로 시작합니다. 개발팀의 기능 상태는 미확인으로 시작합니다. 둘은 다른 뜻입니다. 오른쪽 각 입력란은 편집 가능하며 입력 내용은 이 브라우저에 저장됩니다. 공동 사용 시에는 우측 상단의 백업(JSON) 파일을 전달해 주세요. 민감한 원문이나 단가 정보 자체는 입력하지 말고 자료명·보관 위치만 기재하세요.
02 / Input & Evidence

기초자료 요청·관리

GIVET은 검증용 데이터 구조와 확인 항목을 제시하고, 그룹칸과 개발팀은 원천 자료 및 구축 결과를 나눠서 채웁니다.

02
이 표의 의미 'GIVET 미수령'은 그룹칸이나 개발팀에 자료가 없다는 의미가 아닙니다. 현재 GIVET에 공유된 원천자료가 확인되지 않았다는 뜻입니다. 실물 자료가 있다면 상태를 바꾸고 파일명이나 저장 위치를 입력해 주세요.

데이터·기준자료 요청 매트릭스

원천 자료, 개발 결과, GIVET 검증 관점을 한 줄에서 관리합니다.

01번 계획서 부록 A 반영작성·협의용
번호필요 자료그룹칸 제공 · 확인개발팀 공유 · 확인GIVET 검토 기준(초안)자료 상태담당 / 기한파일명 · 회신 · 메모

※ 그룹칸 제공자료와 개발팀의 데이터 구축 결과는 별개입니다. 원천자료를 받았더라도 DB에 등록·검증됐다는 의미는 아닙니다. ※ CSV는 엑셀에서도 열어볼 수 있습니다.

03 / Functional Readiness

핵심 엔진 점검

전체 제품의 핵심 기능을 '무엇을 만들었는가'뿐 아니라 '무엇을 보여 주면 검증할 수 있는가'의 관점에서 정리합니다.

03
평가 원칙 개발팀의 설계·테스트·구동 결과를 확인하기 전에는 구현 상태를 판단하지 않습니다. 각 엔진의 체크 항목은 GIVET이 확인할 증빙의 예시이며, 자료를 본 뒤 검증 범위를 조정할 수 있습니다.
04 / Test Design

KPI · 시험계획

GIVET이 선제적으로 준비할 수 있는 측정 항목입니다. 목표치는 기존 연구개발계획서의 내용을 참고했으며, 실제 공인시험 전 최종 협약서·시험방법을 재확인해야 합니다.

04

성능지표 및 측정 설계표

시험 증빙과 측정 결과가 나왔을 때 바로 기록할 수 있도록 구성했습니다.

공식 기준 최종 확인 필요
성능지표계획 목표GIVET 시험방법·필요 증빙(초안)현재 확보할 자료시험 상태측정 결과·비고

GIVET 시험 준비 순서

시스템 완성 후에 검증을 시작하지 않도록 합니다.

시험항목 확정: 확정 협약계획서의 KPI 명칭·목표치·성적서 제출 요건 대조
시험 데이터 정의: 입력조건, 기대결과, 근거 원본과 계산 기준 정리
시험환경 협의: 테스트 계정·API·로그·DB 버전·시험 시나리오 확보
예비 검증: 오류 유형·누락 자료·개선 요청을 이력으로 관리
공인시험 지원: 외부 공인시험기관의 관련 인정범위·의뢰 절차·증빙 확인

유의 사항

성적서 발급과 내부 검증의 역할을 구분합니다.

공인시험기관 별도 검토
기존 연구개발계획서에는 위탁연구개발기관을 제외한 공인시험기관에 주요 성능지표 시험을 의뢰한다는 내용이 있습니다. GIVET은 시험방법 설계·예비검증·시험 의뢰 지원을 수행하고, 최종 기관은 해당 시험의 인정범위와 발급 가능 여부를 확인해 결정해야 합니다.

KOLAS 인정기관이라는 사실만으로 모든 SW 성능지표의 공인시험이 가능한 것은 아닙니다. 시험대상·항목별 인정범위를 확인해야 합니다.

05 / Coordination Log

협의 · 후속조치

누가 잘못했는지를 따지는 회의보다, 각 기관이 다음 주에 무엇을 준비할 수 있는지 확정하는 기술협의를 목표로 합니다.

05

기술협의 주요 안건

GIVET이 먼저 준비해 갈 수 있는 질문들입니다.

01

자료를 보유하는 주체, 실제 전달 여부, 공유 가능한 원본 형식과 일정 확인

02
RAG·BoQ·규정 엔진의 구현 상태

현재 기능의 입력·출력 예시 및 향후 연동 일정 확인

03
규정 룰셋 정형화·검토 책임

규정 원문 해석, 표 작성, 판정 로직 구현, 전문가 검증의 담당 구분

04

05
